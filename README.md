# 哔哩哔哩视频画质选择与下载

[![Version](https://img.shields.io/badge/version-0.2.1-00AEEC)](bili-1080p-downloader.user.js) [![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

在 B 站普通视频页面点击下载图标，查看当前分 P 可用的 **1080P、720P、480P、360P 等画质和大小**，选择后保存为带声音的 MP4。使用浏览器已有登录状态，只展示普通账号实际可用的画质。

图标支持拖动、记住位置；点击展开面板，再次点击收起。展开的面板会跟随图标拖动，根据图标位置向上或向下展开，空间不足时内部滚动。

适用于桌面 **Chrome + Tampermonkey（油猴）**。无需安装 FFmpeg、Python 或运行本地服务。

**不建议使用本脚本下载时长较长的视频。** 浏览器需要暂存音视频及合并后的文件，长视频容易占用较多内存。如需下载长视频，推荐使用更专业、功能更丰富的客户端软件 [Bili23-Downloader](https://github.com/ScottSloan/Bili23-Downloader)。

源码仓库：[like-ycy/bili-download-userscript](https://github.com/like-ycy/bili-download-userscript)。问题反馈请提交 [Issue](https://github.com/like-ycy/bili-download-userscript/issues)。

## 安装

1. 使用桌面 Chrome，安装 Tampermonkey，并开启「允许运行用户脚本」。
2. 打开 [bili-1080p-downloader.user.js](bili-1080p-downloader.user.js)，复制完整内容。
3. 在 Tampermonkey 中选择「添加新脚本」，用复制的内容替换默认模板，保存。
4. 刷新 B 站视频页面，确认右下方出现蓝色圆形下载图标。

首次安装会从 jsDelivr 获取固定版本的签名和合并组件。通过编辑器安装的版本，更新时需要用新版源码替换并保存。

## 使用

1. 在 [哔哩哔哩](https://www.bilibili.com/) 登录，打开普通视频；多分 P 视频先切换到想下载的一 P。
2. 点击下载图标，等待列表展示各画质的分辨率、编码与大小。没有 1080P 的视频仍可选择其余可用画质。
3. 点击所需画质旁的「下载」。脚本会更新该档位的地址，下载音视频并无损合并为 MP4。
4. 首次读取媒体大小或下载时，如果油猴询问跨域访问权限，允许访问脚本声明的 B 站媒体域名。
5. 完成后，在 Chrome 下载列表中查看文件。下载目录由浏览器设置决定。

再次点击图标或面板的关闭按钮可收起面板。拖动图标时，面板跟随移动；松手会记住位置，刷新后仍保留。窗口缩小时图标保持在可见范围内。

下载中可以点击「取消下载」，也可以收起面板，再点击图标打开。页面切换视频后旧的画质探测会取消，下一次展开读取新视频；已经开始的下载仍属于点击时的视频和画质。刷新或关闭页面会终止任务。

文件名示例：`视频标题 - BV1rhad63EQB - P1 - 1080P.mp4`。

「已交给浏览器保存」表示 MP4 已生成并触发保存；最终保存状态及目录以 Chrome 下载列表为准。

## 功能与范围

- 支持普通 BV / av 视频及当前分 P；切换视频后重新识别，已经开始的下载始终属于点击时的视频。
- 列出实际返回的普通账号画质，最高为普通 1080P（`qn=80`）；缺少 1080P 时仍展示其余档位。
- 每个画质显示实际分辨率、编码和音视频合计大小，各有独立下载按钮；大小读取失败时明确显示「大小未知」。
- 同一画质优先 H.264，缺少时使用 H.265 或 AV1，音频选择 AAC。H.265 / AV1 成品需要播放器支持相应编码。
- 下载前更新地址，所选画质不可用时明确报错，不自动改成其他画质。
- 在后台 Worker 中直接复制编码数据并重新封装，保持画质和原始音频，无需重新编码。
- 显示下载与合并进度；支持取消，失败后可重试，自动尝试接口返回的备用 CDN 地址。
- 自动清理文件名中的非法字符并限制长度，保留完整的 emoji 和组合字符。
- 合计输入上限为 **512 MiB**（界面显示为 512 MB）。首版暂存完整音视频及输出，大文件请使用桌面下载器。
- 番剧、课程、直播、付费内容和批量下载暂不支持。

## 常见问题

**普通账号可以下载吗？**

可以下载当前账号有权观看的普通画质。最高列出普通 1080P，具体取决于视频提供的档位；1080P 高码率、1080P60 等会员档位不列入列表。

**为什么列表中没有 1080P？**

先确认当前浏览器已登录，并且网页播放器能选择普通 1080P。脚本按接口实际返回的视频轨道判断，只展示实际拿到的档位。没有 1080P 时可以选择列表中的 720P、480P 等版本，也可以点击「刷新列表」重试。

**列表中的大小准确吗？为什么有时显示未知？**

大小来自媒体服务器的响应头，是视频轨与音频轨的合计值，合并后的 MP4 可能略有差异。探测先使用 HEAD，必要时请求一字节范围，获取响应头后停止读取。服务器未提供有效大小时会显示「大小未知」，仍可尝试下载，下载过程中继续检查 512 MB 上限。

**为什么没有下载按钮？**

确认正在普通视频页面（`/video/BV…` 或 `/video/av…`），脚本已启用，Chrome 已允许 Tampermonkey 运行用户脚本，再刷新页面。其他页面不显示下载按钮。

**为什么下载失败，或者提示合并组件未加载？**

媒体下载失败时先检查网络和油猴的域名访问权限，再重试以获取新的播放地址。合并组件加载失败时，确认可以访问 jsDelivr，然后重新安装脚本并刷新页面。

**为什么合并比旧脚本快？**

脚本使用 JavaScript 媒体库在后台线程中直接复制编码包、重写 MP4 容器，省去 FFmpeg WebAssembly 内核的加载和运行开销。具体耗时取决于文件与设备，下面列出了当前样本的测试结果。

## 原理与依赖

使用视频详情接口确定 BV 号与 cid，携带网页登录态调用 WBI 播放接口，读取实际可用的画质与文件大小，选择后下载独立的视频轨和音频轨，再输出标准 MP4。脚本不读取、导出或持久化登录 Cookie；跨域媒体请求限定为 `bilivideo.com` 和 `bilivideo.cn`，不携带登录 Cookie。油猴存储只保存图标位置。

- [blueimp-md5 2.19.0](https://github.com/blueimp/JavaScript-MD5)：MIT，生成 WBI 请求签名。
- [Mediabunny 1.61.4](https://github.com/Vanilagy/mediabunny)：MPL-2.0，在 Worker 中无损封装 MP4。通过油猴资源载入原始发布文件，未修改其源码。

项目以独立 `.user.js` 发布，无需构建。主脚本使用 MIT 许可证；第三方依赖保留各自许可证。

## 开发验证

语法检查：`node --check bili-1080p-downloader.user.js`。

浏览器验证应覆盖：图标拖动、刷新保留位置、面板跟随与展开收起、大小探测、不同画质下载、取消后重试、分 P 切换、未登录和没有 1080P 的列表。下载后用媒体探测工具检查编码、实际尺寸和时长，并验证音画同步和跳转播放。

### 0.2.0 验证

- 在 BV1pshi6DEjQ 页面展开列表，读取到 1080P / 720P / 480P / 360P，音视频合计约 81.0 / 36.2 / 18.4 / 16.2 MB；仅展开面板不会下载。
- 选择 720P 后保存为 1280×720、H.264 + AAC 的 MP4，时长约 162.77 秒，合并约 0.09 秒，完整音视频解码通过。
- 浏览器内验证点击展开收起、指针拖动事件、面板上下定位、边缘约束和窗口缩小；位置通过油猴存储保留。
- 模拟响应验证没有 1080P 时的低画质列表、会员档过滤、大小未知、HEAD 失败后的 Range 探测、服务器忽略 Range 时立即中止、取消和不完整文件拒绝。
- H.265 / AV1 的封装与完整解码使用本地生成的短样本验证；B 站实测样本优先使用 H.264。

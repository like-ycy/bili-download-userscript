# 哔哩哔哩 1080P 下载

[![Version](https://img.shields.io/badge/version-0.1.0-00AEEC)](bili-1080p-downloader.user.js) [![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

在 B 站普通视频页面点击「下载 1080P」，下载当前分 P，保存为带声音的 MP4。使用浏览器已有登录状态，普通账号可以下载其有权观看的普通 1080P。

适用于桌面 **Chrome + Tampermonkey（油猴）**。无需安装 FFmpeg、Python 或运行本地服务。

源码仓库：[like-ycy/bili-download-userscript](https://github.com/like-ycy/bili-download-userscript)。问题反馈请提交 [Issue](https://github.com/like-ycy/bili-download-userscript/issues)。

## 安装

1. 使用桌面 Chrome，安装 Tampermonkey，并开启「允许运行用户脚本」。
2. 打开 [bili-1080p-downloader.user.js](bili-1080p-downloader.user.js)，复制完整内容。
3. 在 Tampermonkey 中选择「添加新脚本」，用复制的内容替换默认模板，保存。
4. 刷新 B 站视频页面，确认右下方出现「↓ 下载 1080P」。

首次安装会从 jsDelivr 获取固定版本的签名和合并组件。通过编辑器安装的版本，更新时需要用新版源码替换并保存。

## 使用

1. 在 [哔哩哔哩](https://www.bilibili.com/) 登录，打开普通视频；多分 P 视频先切换到想下载的一 P。
2. 点击「↓ 下载 1080P」。脚本会解析当前视频，下载视频和音频，再无损合并为 MP4。
3. 首次下载时，如果油猴询问跨域访问权限，允许访问脚本声明的 B 站媒体域名。
4. 完成后，在 Chrome 下载列表中查看文件。下载目录由浏览器设置决定。

下载中可以点击「取消」，也可以收起面板，再点「查看下载进度」打开。页面切换视频后，已经开始的任务仍下载点击时的那一条；刷新或关闭页面会终止任务。

文件名示例：`视频标题 - BV1rhad63EQB - P1 - 1080P.mp4`。

「已交给浏览器保存」表示 MP4 已生成并触发保存；最终保存状态及目录以 Chrome 下载列表为准。

## 功能与范围

- 支持普通 BV / av 视频及当前分 P；切换视频后重新识别，已经开始的下载始终属于点击时的视频。
- 严格选择普通 1080P（`qn=80`），使用 H.264 视频与 AAC 音频，不自动降画质。
- 在后台 Worker 中直接复制编码数据并重新封装，保持画质和原始音频，无需重新编码。
- 显示下载与合并进度；支持取消，失败后可重试，自动尝试接口返回的备用 CDN 地址。
- 自动清理文件名中的非法字符并限制长度，保留完整的 emoji 和组合字符。
- 合计输入上限为 **512 MiB**（界面显示为 512 MB）。首版暂存完整音视频及输出，大文件请使用桌面下载器。
- 番剧、课程、直播、付费内容、批量下载和 HEVC / AV1 暂不支持。没有提供 1080P 的视频会明确提示。

## 常见问题

**普通账号可以下载吗？**

可以下载当前账号有权观看的普通 1080P。视频本身也必须提供这个档位；1080P 高码率、1080P60 等属于其他档位。

**为什么提示没有取得 1080P？**

先确认当前浏览器已登录，并且网页播放器能选择普通 1080P。脚本按接口实际返回的视频轨道判断，拿不到时会提示原因，不会悄悄改为 720P。

**为什么没有下载按钮？**

确认正在普通视频页面（`/video/BV…` 或 `/video/av…`），脚本已启用，Chrome 已允许 Tampermonkey 运行用户脚本，再刷新页面。其他页面不显示下载按钮。

**为什么下载失败，或者提示合并组件未加载？**

媒体下载失败时先检查网络和油猴的域名访问权限，再重试以获取新的播放地址。合并组件加载失败时，确认可以访问 jsDelivr，然后重新安装脚本并刷新页面。

**为什么合并比旧脚本快？**

脚本使用 JavaScript 媒体库在后台线程中直接复制编码包、重写 MP4 容器，省去 FFmpeg WebAssembly 内核的加载和运行开销。具体耗时取决于文件与设备，下面列出了当前样本的测试结果。

## 原理与依赖

使用视频详情接口确定 BV 号与 cid，携带网页登录态调用 WBI 播放接口，下载独立的视频轨和音频轨，再输出标准 MP4。脚本不读取、导出或持久化登录 Cookie；跨域媒体请求限定为 `bilivideo.com` 和 `bilivideo.cn`，不携带登录 Cookie。

- [blueimp-md5 2.19.0](https://github.com/blueimp/JavaScript-MD5)：MIT，生成 WBI 请求签名。
- [Mediabunny 1.61.4](https://github.com/Vanilagy/mediabunny)：MPL-2.0，在 Worker 中无损封装 MP4。通过油猴资源载入原始发布文件，未修改其源码。

项目以独立 `.user.js` 发布，无需构建。主脚本使用 MIT 许可证；第三方依赖保留各自许可证。

### 首版实测

2026-10-14，在已登录的桌面 Chrome + Tampermonkey 5.5.1 中验证：

| 视频 | 文件大小 | 分辨率 / 编码 | 合并耗时 |
| --- | --- | --- | --- |
| BV1rhad63EQB，约 120 秒 | 37.7 MiB | 1920×1080，H.264 + AAC | 约 0.10 秒 |
| BV1pshi6DEjQ，约 163 秒 | 81.0 MiB | 1920×1080，H.264 + AAC | 约 0.17 秒 |

耗时为样本的 Worker 内封装时间，不含下载和 Worker 初始化，随设备和文件变化。第一份成品完整解码通过，所有音视频编码包与原始轨道的 SHA-256 相同；Chrome 跳转 1、60、115 秒正常。已验证取消后重试和网页自动连播切换视频。未登录、缺少 1080P、缺少音轨、当前分 P 参数和地址边界通过模拟响应验证，尚未覆盖真实多分 P 视频及接近 512 MiB 的大文件。

# 哔哩哔哩视频与图集下载

[![Version](https://img.shields.io/badge/version-0.3.3-00AEEC)](bili-1080p-downloader.user.js) [![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

在 B 站普通视频页面点击下载图标，查看当前分 P 可用的 **1080P、720P、480P、360P 等画质和大小**，选择后保存为带声音的 MP4。使用浏览器已有登录状态，只展示普通账号实际可用的画质。

在动态图集详情页点击同一个图标，可查看全部**原图链接、尺寸和大小**，逐张下载，或将整组原图打包为 ZIP。

图标支持拖动、记住位置；点击展开面板，再次点击收起。展开的面板会跟随图标拖动，根据图标位置向上或向下展开，空间不足时内部滚动。

适用于桌面 **Chrome + Tampermonkey（油猴）**，建议两者均更新到最新版。无需安装 FFmpeg、Python 或运行本地服务。手机浏览器、其他脚本管理器及旧版浏览器尚未验证。

**不建议使用本脚本下载时长较长的视频。** 浏览器需要暂存音视频及合并后的文件，长视频容易占用较多内存。如需下载长视频，推荐使用更专业、功能更丰富的客户端软件 [Bili23-Downloader](https://github.com/ScottSloan/Bili23-Downloader)。

源码仓库：[like-ycy/bili-download-userscript](https://github.com/like-ycy/bili-download-userscript)。问题反馈请提交 [Issue](https://github.com/like-ycy/bili-download-userscript/issues)。

## 安装

1. 使用桌面 Chrome，安装 Tampermonkey，并开启「允许运行用户脚本」。
2. 打开 [bili-1080p-downloader.user.js](bili-1080p-downloader.user.js)，复制完整内容。
3. 在 Tampermonkey 中选择「添加新脚本」，用复制的内容替换默认模板，保存。
4. 刷新 B 站视频或动态详情页面，确认右下方出现蓝色圆形下载图标。

保存脚本后再刷新已经打开的 B 站标签页。更新时编辑原有脚本，避免同时启用多个版本。

首次安装会从 jsDelivr 获取固定版本的签名、合并和 ZIP 组件。通过编辑器安装的版本，更新时需要用新版源码替换并保存；从旧版升级后，需允许新增的 `hdslb.com` 图片域名访问权限。

## 使用

1. 在 [哔哩哔哩](https://www.bilibili.com/) 登录，打开普通视频；多分 P 视频先切换到想下载的一 P。
2. 点击下载图标，等待列表展示各画质的分辨率、编码与大小。没有 1080P 的视频仍可选择其余可用画质。
3. 点击所需画质旁的「下载」。脚本会更新该档位的地址，下载音视频并无损合并为 MP4。
4. 首次读取媒体大小或下载时，如果油猴询问跨域访问权限，允许访问脚本声明的 B 站媒体域名。
5. 完成后，在 Chrome 下载列表中查看文件。下载目录由浏览器设置决定。

再次点击图标或面板的关闭按钮可收起面板。拖动图标时，面板跟随移动；松手会记住位置，刷新后仍保留。窗口缩小时图标保持在可见范围内。

下载中可以点击「取消下载」，也可以收起面板，再点击图标打开。页面内切换视频后旧的画质探测会取消，下一次展开读取新视频；已经开始的下载仍属于点击时的视频和画质。刷新、关闭标签页或跳转到需要重新加载的页面会终止任务；任务进行时脚本会请求浏览器弹出离开提醒，请选择留在页面。浏览器崩溃、强制退出或部分页面关闭场景无法保证弹出提醒。

文件名示例：`用户名 - 视频标题 - P1 - 1080P.mp4`，以视频作者的用户名开头，不再附加 BV 号。

「已交给浏览器保存」表示 MP4 已生成并触发保存；最终保存状态及目录以 Chrome 下载列表为准。面板会保留「重新保存文件」链接 60 秒，浏览器没有开始保存时可手动点击，无需重新下载；开始新任务会清除这个链接。已经保存成功时不用再点，以免生成重复文件。

### 图集下载

1. 打开图集动态详情页（`https://www.bilibili.com/opus/动态ID` 或 `https://t.bilibili.com/动态ID`）。
2. 点击下载图标，面板按发布顺序列出原图尺寸、原始格式和估计大小。「查看原图」可打开或复制原图链接。
3. 点击某张图片旁的「下载」，保存其原始文件；点击「下载全部原图（ZIP）」，保存包含全部图片的 ZIP。
4. 图片、ZIP 及压缩包内的图片文件名均以作者用户名开头，随后是动态标题或文字、动态 ID；图片还带有顺序编号。例如 `用户名 - 动态标题 - 动态ID - 01.jpg`、`用户名 - 动态标题 - 动态ID.zip`。ZIP 在后台 Worker 中打包，不重新编码或压缩图片，保留原始文件字节及格式；取消会立即终止后台打包。

「下载全部原图」「刷新列表」和下载进度均位于图片列表上方，无需滚动到底部操作。

图集单次下载合计上限为 512 MiB，支持取消和失败后重试；预计超过上限时会提示分张下载。任一图片失败时不会输出缺图的 ZIP。下载开始后在页面内切换内容，任务仍属于点击时的图集；刷新或关闭页面会终止任务。完成状态表示文件已交给浏览器，也可在 60 秒内点击「重新保存文件」，最终保存情况以 Chrome 下载列表为准。

## 功能与范围

- 支持普通 BV / av 视频及当前分 P；切换视频后重新识别，已经开始的下载始终属于点击时的视频。
- 支持动态详情页的图集原图，逐张保存或全部打包为一个 ZIP；保留发布顺序和原始格式，显示原图链接、尺寸与估计大小。
- 列出实际返回的普通账号画质，最高为普通 1080P（`qn=80`）；缺少 1080P 时仍展示其余档位。
- 每个画质显示实际分辨率、编码和音视频合计大小，各有独立下载按钮；大小读取失败时明确显示「大小未知」。
- 同一画质优先 H.264，缺少时使用 H.265 或 AV1，音频选择 AAC。H.265 / AV1 成品需要播放器支持相应编码。
- 下载前更新地址，所选画质不可用时明确报错，不自动改成其他画质。
- 在后台 Worker 中直接复制编码数据并重新封装，保持画质和原始音频，无需重新编码。
- 显示下载与合并进度；支持取消，失败后可重试，自动尝试接口返回的备用 CDN 地址。
- 脚本独立控制请求超时：每次媒体下载最多等待 15 分钟，单次大小探测 10 秒，B 站接口请求 20 秒。即使油猴没有报告实时进度，也不会无限等待。
- 自动清理文件名中的非法字符并限制长度，保留完整的 emoji 和组合字符。
- 合计输入上限为 **512 MiB**（界面显示为 512 MB）。首版暂存完整音视频及输出，大文件请使用桌面下载器。
- 番剧、课程、直播、付费内容、专栏、转发动态和跨稿件批量下载暂不支持。动态列表页不提供批量图集下载。

## 常见问题

**普通账号可以下载吗？**

可以下载当前账号有权观看的普通画质。最高列出普通 1080P，具体取决于视频提供的档位；1080P 高码率、1080P60 等会员档位不列入列表。

**为什么列表中没有 1080P？**

先确认当前浏览器已登录，并且网页播放器能选择普通 1080P。脚本按接口实际返回的视频轨道判断，只展示实际拿到的档位。没有 1080P 时可以选择列表中的 720P、480P 等版本，也可以点击「刷新列表」重试。

**列表中的大小准确吗？为什么有时显示未知？**

大小来自媒体服务器的响应头，是视频轨与音频轨的合计值，合并后的 MP4 可能略有差异。探测先使用 HEAD，必要时请求一字节范围，获取响应头后停止读取。服务器未提供有效大小时会显示「大小未知」，仍可尝试下载，下载过程中继续检查 512 MB 上限。

**为什么没有下载按钮？**

确认正在普通视频页面（`/video/BV…` 或 `/video/av…`）或动态详情页（`/opus/…`、`t.bilibili.com/动态ID`），脚本已启用，Chrome 已允许 Tampermonkey 运行用户脚本，再刷新页面。其他页面不显示下载按钮；非图集动态会提示暂不支持。

安装后仍无图标时，先将 Chrome 和 Tampermonkey 更新到最新版，在 Chrome 的扩展管理中查看 Tampermonkey 是否允许在 B 站运行，并检查「允许运行用户脚本」设置。脚本依赖 jsDelivr，组件下载未完成或失败时也可能无法运行。

**为什么下载失败，或者提示合并组件未加载？**

媒体下载失败时先检查网络和油猴的域名访问权限，再重试以获取新的播放地址。合并组件加载失败时，确认可以访问 jsDelivr，然后重新安装脚本并刷新页面。

脚本会在开始下载前检查合并或 ZIP 组件是否存在，组件缺失时会提前提示；单张原图下载不需要 ZIP 组件。这项检查不能保证组件一定能启动，浏览器限制或资源损坏仍可能在合并、打包阶段报错。

如果之前拒绝了域名访问，需在 Tampermonkey 中重新允许对应域名，具体位置随版本而异；只刷新页面不一定会再次弹出授权询问。视频需要 `bilivideo.com` / `bilivideo.cn`，原图需要 `hdslb.com`，包括它们的子域名。

**提示未登录、请求受限或接口异常怎么办？**

- 未登录或登录过期（`-101`）：先在同一浏览器登录 B 站，确认网页能播放视频，再点击「刷新列表」。
- 请求暂时受限（HTTP `412` / `429`，或 `-352` / `-412`）：先暂停操作，稍后再试，避免连续刷新和反复点击下载。
- 签名请求反复失败（`-403`）：刷新列表；仍失败时检查电脑日期、时间和时区是否正确，建议开启系统自动校时。
- 返回内容无法读取、格式异常或超时：检查网络，稍后刷新列表。持续失败时可能是 B 站接口变化，可提交 Issue。

**显示「已交给浏览器保存」，但找不到文件怎么办？**

打开 Chrome 菜单中的「下载内容」，查看是否已完成、被拦截、保存失败或仍等待选择目录；保存位置由 Chrome 的下载设置决定。脚本无法读取最终落盘状态。如果没有下载记录，在 60 秒内点面板中的「重新保存文件」。若浏览器提示拦截多个自动下载，可在该站点的权限设置中允许自动下载，再点击重新保存。链接消失后需要重新下载。

**网速慢、进度不动，或者下载中断后能续传吗？**

每次媒体请求最多等待 15 分钟，到时仍未完成就会中止；视频会继续尝试接口提供的备用地址，仍失败时显示错误。油猴未提供实时进度时，界面可能暂时不更新，可以继续等待或点击「取消下载」。切换备用地址会重新下载对应音轨或视频轨，进度可能回退。手动重试和取消后重试都会重新开始整个任务，暂不支持断点续传。

下载期间保留标签页，避免电脑休眠；浏览器挂起页面、系统休眠或网络断开都可能打断任务。512 MB 是输入文件大小上限，并非内存占用上限，合并和打包还会产生额外内存开销。页面卡顿、崩溃或合并超时时，可改用较低画质、分张下载图片或使用桌面下载器。

**MP4 下载成功，但播放器黑屏、只有声音或无法播放？**

查看下载列表中的编码。H.265 / AV1 需要播放器支持相应编码，可以换用支持该编码的播放器。脚本只合并原始音视频，不会把 H.265 / AV1 转成 H.264；有 H.264 时已优先选择它。如果 H.264 文件也无法播放，可重新下载并确认 Chrome 下载列表显示完成。

**反馈问题时提供什么信息？**

请附上视频或图集页面链接、所选分 P 和画质、脚本版本、Chrome / Tampermonkey 版本、面板中的完整错误提示，以及失败发生在读取列表、下载、合并还是保存阶段。无需提供 Cookie、登录凭据或带签名的媒体直链。

**为什么合并比旧脚本快？**

脚本使用 JavaScript 媒体库在后台线程中直接复制编码包、重写 MP4 容器，省去 FFmpeg WebAssembly 内核的加载和运行开销。具体耗时取决于文件与设备，下面列出了当前样本的测试结果。

## 原理与依赖

使用视频详情接口确定 BV 号与 cid，携带网页登录态调用 WBI 播放接口，读取实际可用的画质与文件大小，选择后下载独立的视频轨和音频轨，再输出标准 MP4。图集通过动态详情接口读取原图清单，去掉缩略图参数，逐张下载或使用 ZIP 原样打包。

脚本不读取、导出或持久化登录 Cookie；视频请求限定为 `bilivideo.com` 和 `bilivideo.cn`，图片请求限定为 `hdslb.com` 的图集路径（`/bfs/new_dyn/`、`/bfs/album/`），跨域媒体请求均不携带登录 Cookie。油猴存储只保存图标位置。

- [blueimp-md5 2.19.0](https://github.com/blueimp/JavaScript-MD5)：MIT，生成 WBI 请求签名。
- [Mediabunny 1.61.4](https://github.com/Vanilagy/mediabunny)：MPL-2.0，在 Worker 中无损封装 MP4。通过油猴资源载入原始发布文件，未修改其源码。
- [JSZip 3.10.1](https://github.com/Stuk/jszip)：MIT / GPLv3 双许可证，本项目按 MIT 使用，将原图打包为 ZIP。

项目以独立 `.user.js` 发布，无需构建。主脚本使用 MIT 许可证；第三方依赖保留各自许可证。

## 开发验证

语法检查：`node --check bili-1080p-downloader.user.js`。

浏览器验证应覆盖：图标拖动、刷新保留位置、面板跟随与展开收起、大小探测、不同画质下载、取消后重试、分 P 切换、未登录和没有 1080P 的列表。还应覆盖没有进度事件的慢速下载、15 分钟媒体超时、10 秒探测超时、Range 被忽略时的流取消、下载中尝试刷新或关闭、保存被拦截后手动重新保存、链接到期及新任务清理。下载后用媒体探测工具检查编码、实际尺寸和时长，并验证音画同步和跳转播放。

图集验证应覆盖：原图数量与顺序、原图地址不含缩略图参数、单张文件、ZIP 全部条目的字节一致性、取消及失败后重试、页面切换、非图集动态、非法图片地址与 512 MiB 上限。

请求适配需遵守 [Tampermonkey 的 GM_xmlhttpRequest 契约](https://www.tampermonkey.net/documentation.php?q=GM_xmlhttpRequest&locale=en)：`anonymous: true` 强制使用 Fetch，Chrome 中内置 `timeout` 不生效，`readystatechange` 只有 DONE。脚本因此自行计时，Range 探测通过 `responseType: 'stream'` 的 `onloadstart` 取得响应头后取消流；验证时不能假定一定有实时进度或 `readyState=2` 回调。
